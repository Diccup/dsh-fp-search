# 01 · magpie-websearch 的免费通道：我们该抄什么、缺什么

> 建立：2026-11-08 17:4x ｜ 作者：泡泡 ｜ 对象：`ctx({op:"search"})` 的引擎层
> 来源：https://github.com/guotree/magpie-websearch （README + docs/technical-reference.md + 一个 provider 源码）
> **范围：只记免费通道。收费/需 Key 的一律不记。**
> **标注规则**：标「实测」= 泡泡本轮在本机真发过请求，有状态码和耗时；标「文档」= 只从它文档读到，**没验**。

---

## 〇 一句话

对岸的「免费」只有 **4 家真匿名**（AnySearch / Keenable / Parallel / TinyFish）。
它值钱的不是引擎数量，而是三个我们**目前完全没有**的机制：
**匿名 429 冷却**、**结果缓存 TTL**、**查询归一 + 时间过滤**。
我们现有 17 家裸抓 HTML 引擎不缺数量，缺的是这三条和「有正文、有日期」的 API 级结果。

---

## 一、真·免费通道（实测过，可零 Key 用）

| 通道 | 匿名端点 | 形态 | 实测结果 | 返回里值钱的字段 |
|---|---|---|---|---|
| **AnySearch** | `https://api.anysearch.com/v1/search` | POST JSON，省略 Authorization | **200 / 2.15s** | `title` `url` `snippet` + **`content`（长正文）** |
| **Keenable** | `https://api.keenable.ai/v1/search/public` | POST JSON，带 `X-Keenable-Title` | **200 / 0.82s** | `mode` `title` `url` `snippet` `description` |
| **Parallel** | `https://mcp.parallel.ai/mcp` | MCP JSON-RPC `tools/call` → `web_search` | **200 / 1.68s / 53KB** | **`publish_date`** + **`excerpts`（正文摘录，可拼接成 text）** |
| **TinyFish** | `https://agent.tinyfish.ai/mcp` | MCP，带 `X-TinyFish-Access-Mode: keyless` | **200 / 1.5–2.35s** | `date` `site_name` `snippet`（中文查询质量好） |
| Exa（备选） | `https://mcp.exa.ai/mcp` | MCP，`web_search_exa` | **200 / 1.23s**（**必须带浏览器 UA**，不带 403） | Title/URL 纯文本块 |
| Firecrawl（备选） | 官方免 Key 匿名额度 | REST（文档） | **未验** | 正文抓取强 |

**调用要点（Parallel，踩过一次）**：`web_search` 必须同时给 `objective` 和 `search_queries`（数组），
只给 objective 会被判 `isError` 并回「Missing required argument: search_queries」。
**响应是 SSE**（`event: message\ndata: {...}`），不是纯 JSON，解析要先剥 `data:` 前缀。

**实测不通的免费路**：Tavily keyless → **401**（文档说可匿名，本机口径不成立）；
You.com → **403**；`s.jina.ai` → 12s 超时；
SearXNG 公网池（searx.be / searx.tiekoetter.com / search.inetol.net / priv.au）→ **全部 10s 超时**。
这四条**别接**。

## 二、我们该抄的三个机制（对岸有，我们零）

### 2.1 匿名 429 冷却 + Retry-After —— 优先级最高

- **现状证据**：`ours/ws-transport.js` 里 `retry` / `backoff` / `429` **命中数全是 0**。
  现在某家被限流（开发日志记过 openalex 429、bilibili 412），行为是**白等到超时再算失败**，
  而且下一次查询**照样再打一遍**。
- **对岸做法**：429 时按 `Retry-After`（秒或 HTTP 日期）冷却该**最终端点**，
  缺失/无效/过期则默认 **60s**；冷却期内新请求**直接本地返回 429，不再连远端**；
  缓存里的结果照常可读。
- **落点**：`ws-transport.js` 加一张 `Map<endpoint, untilTs>`，`load()` 入口查表。
  纯内存、无依赖、跨引擎共用——**不动任何引擎卡**。
- **判据**：人为让某家返 429，第二次查询应**<50ms 返回**且不再发网络请求。

### 2.2 结果缓存 TTL —— 性价比最高的省时

- **现状证据**：`ours/web-search.js` 里 `cache` **0 处**、`ttl` 只出现在 Promise 的变量名里。
  实测同题重查：`search("秘塔搜索 API 价格")` 每次都要 **2.87s**（17 家并行，墙钟钉子）。
- **对岸做法**：默认 **600s** 缓存，键 = 端点 + 请求体 + key 的合并哈希；`cacheTTL:0` 可关。
- **落点**：`web-search.js` 聚合层按 `query + engines + limit` 缓存**最终合并结果**（不是缓存每家原始 HTML），
  命中直接回，省掉全部并行请求。
- **判据**：同参第二次 `search()` 耗时应 **<100ms**；换 query 必须不命中。

### 2.3 查询归一 + 时间过滤 —— 补「最近 N 天」这个空白

- **现状**：17 家引擎**没有一家**支持时间维度；问「最近三天」只能靠 Bing 的 tbs 手工拼，
  或者干脆答不出来。另外 query 不夹长度（Parallel 官方限制 1–200 字符）。
- **对岸做法**：统一 `normalizeQuery`（空白折叠 + trim）；时间参数按引擎各自映射：
  AnySearch 忽略时间；Parallel/Exa 走各自日期字段；TinyFish/Keenable 无时间参数。
  近似档的通用口径：`≤2天→day`、`≤14天→week`、`≤90天→month`，其余 `year`。
- **落点**：① `resolveOpts` 里加 `normalizeQuery`（纯字符串处理，零风险）；
  ② 卡片契约加可选 `timeParam(days)` 槽，**只有支持时间的卡才实现**，不支持的静默忽略。
- **判据**：`search(q,{days:3})` 在支持时间的卡上必须带上对应参数，其余卡行为不变。

## 三、我们缺的引擎（免费、可零成本接）

按「我们现在做不到什么」来选，不是按对岸有几家：

| 缺口 | 现在 | 接了之后 |
|---|---|---|
| 结果只有 60 字 snippet | 抓 HTML 只能拿到摘要 | **AnySearch `content` / Parallel `excerpts`** 直接给正文级 |
| 没有发布时间 | 全部引擎都没有 | **Parallel `publish_date`** / TinyFish `date` |
| 中文时效内容弱 | 靠 baidu/sogou 抓页，常被风控 | **TinyFish 中文实测 1.5s 命中** |

**接法与现有结构天然兼容**：卡片契约里 `run(query, limit, ctx)` 这条路已经给「自定义抓取」留了槽
（bilibili / mso / baidu 就是自己跑逻辑），API 引擎**同样是一张卡、一个文件**，
符合 `20-引擎积木化总清单` 的「新加引擎 = 只加一个文件」。

**建议顺序**：TinyFish（中文最好）→ Parallel（有日期，时效查询最强）→ AnySearch（有长正文）。
Keenable 可作备选（最快 0.82s，但字段最薄）。Exa 需伪装 UA，除非主人点名，暂不接。

---

## 四、要主人拍板的三件

1. **P0 两条要不要先落**：429 冷却 + 结果缓存（都不动引擎卡、不改变返回文本，只影响耗时与稳定性）。
2. **API 引擎接不接**：接的话先接哪家（泡泡建议 TinyFish 起手，中文最稳）。
3. **时间过滤做不做**：做的话是「先只有新 API 卡支持」（改动小）还是「连老引擎一起改」（动 17 张卡）。

## 附 · 复现命令

```python
# AnySearch 匿名（免 Key）
POST https://api.anysearch.com/v1/search
{"query":"DeepSeek V4","max_results":3,"format":"json"}

# Keenable 匿名
POST https://api.keenable.ai/v1/search/public   header: X-Keenable-Title: dsh-test
{"query":"DeepSeek V4","max_results":3}

# Parallel 匿名（注意 objective + search_queries 两个都要）
POST https://mcp.parallel.ai/mcp   header: Accept: application/json, text/event-stream
{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"web_search","arguments":{"objective":"...","search_queries":["..."]}}}

# TinyFish 匿名
POST https://agent.tinyfish.ai/mcp   header: X-TinyFish-Access-Mode: keyless
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"search","arguments":{"query":"..."}}}
```

> 注意：本机 `ctx({op:"search",url:...})` 抓 `github.com` / `raw.githubusercontent.com` 会 504/超时，
> 走 ctx 抓对岸文档要重试；上面这几个 API 端点用 python `urllib` 直连是通的。
