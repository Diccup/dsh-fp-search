# 02 · 六个免费通道连通性实测（能不能用，怎么才通）

> 建立：2026-11-08 18:0x ｜ 作者：泡泡 ｜ 回答：主人问「这 6 家我们都能连通吗」
> **测试环境**：本机 Python `urllib` + **本机 Node `fetch`**（插件就跑在 Node 里，Node 通才算真通）
> **判定口径**：`200` 且拿到带标题/正文的结果 = 通；只有报错码不算。

---

## 〇 结论一句话

**6 家全部能连通，Node 环境也全通**（不是只能在 python 里通）。
但有 **3 家必须先满足前置条件**才给 200，另有 **1 家（Exa）有硬限流**。
→ 可用的核心是 **AnySearch / Keenable / Parallel / TinyFish / Firecrawl 这 5 家**，Exa 只能当替补。

---

## 一、总表（Node fetch 实测，中文查询「DeepSeek 最新动态」）

| # | 通道 | 状态 | 耗时 | 返回体积 | 前置条件 |
|---|---|---|---|---|---|
| 1 | **AnySearch** | ✅ 200 | 1.6s | 4.2KB | 无（裸 POST JSON 即可） |
| 2 | **Keenable** | ✅ 200 | 0.9s | 3.2KB | **必须带 `X-Keenable-Title` 头** |
| 3 | **Parallel** | ✅ 200 | 2.0s | 42KB | 无（但 `web_search` 要两个参数） |
| 4 | **TinyFish** | ✅ 200 | 0.5s | 3.8KB | **必须带 `X-TinyFish-Access-Mode: keyless`** |
| 5 | **Firecrawl** | ✅ 200 | 1.0s | 0.7KB | 无（裸 POST JSON 即可） |
| 6 | **Exa** | ⚠️ 200 但限流 | 1.4s | 4.6KB | **必须带浏览器 UA + Accept: SSE**；并发超 2 就 429 |

**全部 6 家在任何时刻都没出现过 DNS/连接失败**——通道本身都在墙外可达，不用梯子。

---

## 二、每家「怎么才通」的精确条件（去掉就失败，实测）

### 2.1 Keenable —— 少一个头就 400

| 请求头 | 结果 |
|---|---|
| 只有 `Content-Type: application/json` | **400** `{"error":"Missing app identifier", "message":"X-Keenable-Title header is required for token-less requests"}` |
| 加上 `X-Keenable-Title: <任意字符串>` | **200** ✅ |

→ 这个头**不是可选装饰，是硬门槛**。值随便填（对岸填的是插件名），但必须存在。

### 2.2 TinyFish —— 少一个头就 401

| 请求头 | 结果 |
|---|---|
| `Content-Type` + `Accept: SSE` | **401** |
| 再加 `X-TinyFish-Access-Mode: keyless` | **200** ✅ |

→ 少了 `keyless` 这个头，服务器就认为你要走付费 Key 路线，于是要鉴权。

### 2.3 Exa —— 两个头都要，而且有并发硬顶

| 请求头 | 结果 |
|---|---|
| 只有 `Content-Type` | **406** |
| 加 `Accept: application/json, text/event-stream` | **200**（但仍需 UA，否则 403） |
| 加浏览器 UA + Accept SSE | **200** ✅ |

**限流实测**（每批 4 并发 × 3 批）：

```
batch0  200 200 429(Retry-After:1) 200
batch1  200 200 429(Retry-After:1) 200
batch2  200 200 429(Retry-After:1) 200
```

→ **匿名 Exa 稳定在第 3 个并发就 429**，每批必定掉一个。回 `Retry-After: 1`（1 秒）。
→ 结论：**Exa 不能进并行聚合**（我们现在是 17 家并发），只能当「单独指定引擎」用，或排在最后。

### 2.4 Parallel —— 参数少一个就 isError

```
只给 objective          → isError: "Missing required argument: search_queries"
objective + search_queries → 200 ✅
```

→ `search_queries` 是**数组**，不是字符串。响应是 **SSE**（`event: message\ndata: {...}`），要先剥 `data:` 前缀。

### 2.5 AnySearch / Firecrawl —— 真·裸奔，无任何前置

两个都只需要 `Content-Type: application/json` + 一个 JSON body。
Firecrawl 的返回最薄（737B，只有 title/url/description），但**正文抓取是它的强项**（要用 `/v1/scrape`）。

## 三、抗压能力（并发会不会炸）

每家同瞬间 **8 个并发**：

| 通道 | 8 并发结果 | 判定 |
|---|---|---|
| AnySearch | `{"200":8}` | ✅ 稳 |
| Keenable | `{"200":8}` | ✅ 稳 |
| Parallel | `{"200":8}` | ✅ 稳 |
| TinyFish | `{"200":8}` | ✅ 稳 |
| Firecrawl | `{"200":8}` | ✅ 稳 |
| **Exa** | `{"200":4, "429":4}` | ❌ **掉一半** |

→ 前 5 家可以直接进并行聚合；**Exa 不行**。

---

## 四、返回内容质量（同样问「DeepSeek 最新动态」）

| 通道 | 拿到什么 | 值钱在哪 |
|---|---|---|
| **AnySearch** | `title` `url` `snippet` + **`content`（长正文段）** | 唯一带长正文的 |
| **Parallel** | **`publish_date`** + **`excerpts[]`（正文摘录，可拼成整段）** | 唯一有结构化日期的 |
| **TinyFish** | `date` `site_name` `snippet` | 中文命中准，`site_name` 直接给 |
| **Exa** | `Title:` / `URL:` / `Published:` / `Highlights:` 纯文本块 | 有 Published 和 Highlights |
| **Keenable** | `mode` `title` `url` `snippet` `description` | 最快（0.9s），字段最薄 |
| **Firecrawl** | `title` `url` `description` | 最薄（737B），强项在 scrape 不在 search |

**质量排序（泡泡判断）**：Parallel（有日期+摘录）＞ AnySearch（有长正文）＞ Exa（有 Highlights）＞ TinyFish（中文准）＞ Keenable（快但薄）＞ Firecrawl（最薄）。

---

## 五、接入建议（按「能不能直接进并行」分档）

### 第一档 · 直接可接（无前置、抗 8 并发）

- **TinyFish** — 中文最好，0.5s，只要记住带 `keyless` 头
- **Parallel** — 唯一有 `publish_date`，时效查询最强，2.0s / 42KB（体积大要截断）
- **AnySearch** — 唯一有长正文 `content`，1.6s
- **Keenable** — 最快 0.9s，带 `X-Keenable-Title` 头即可

### 第二档 · 可接但要改装

- **Firecrawl** — search 结果太薄，真正价值在 `/v1/scrape` 抓正文。可以接成「page 腿的补充」，不是搜索引擎。

### 第三档 · 不建议进聚合

- **Exa** — 并发 3 就 429，且要伪装 UA。接了会让整个并行聚合变慢（等 Retry-After）。**只能当「单引擎指定」备选。**

## 附 · 现场复现（Node，与插件同环境）

```js
const UA = 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36';
const SSE = {'Content-Type':'application/json','Accept':'application/json, text/event-stream','User-Agent':UA};

// 1 AnySearch  —— 无前置
fetch('https://api.anysearch.com/v1/search', {method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({query:'DeepSeek 最新动态', max_results:3, format:'json'})});

// 2 Keenable  —— 必须 X-Keenable-Title
fetch('https://api.keenable.ai/v1/search/public', {method:'POST',
  headers:{'Content-Type':'application/json','X-Keenable-Title':'dsh-test'},
  body: JSON.stringify({query:'DeepSeek 最新动态', max_results:3})});

// 3 Parallel  —— objective + search_queries 两个都要；SSE 响应
fetch('https://mcp.parallel.ai/mcp', {method:'POST', headers:SSE,
  body: JSON.stringify({jsonrpc:'2.0',id:1,method:'tools/call',
    params:{name:'web_search',arguments:{objective:'DeepSeek latest',search_queries:['DeepSeek 最新动态']}}})});

// 4 TinyFish  —— 必须 X-TinyFish-Access-Mode
fetch('https://agent.tinyfish.ai/mcp', {method:'POST',
  headers:{...SSE,'X-TinyFish-Access-Mode':'keyless'},
  body: JSON.stringify({jsonrpc:'2.0',id:1,method:'tools/call',
    params:{name:'search',arguments:{query:'DeepSeek 最新动态'}}})});

// 5 Firecrawl —— 无前置（但结果薄）
fetch('https://api.firecrawl.dev/v1/search', {method:'POST',
  headers:{'Content-Type':'application/json'},
  body: JSON.stringify({query:'DeepSeek 最新动态', limit:3})});

// 6 Exa  —— 必须 UA + Accept SSE；并发 ≤2
fetch('https://mcp.exa.ai/mcp', {method:'POST', headers:SSE,
  body: JSON.stringify({jsonrpc:'2.0',id:1,method:'tools/call',
    params:{name:'web_search_exa',arguments:{query:'DeepSeek 最新动态',numResults:3}}})});
```
